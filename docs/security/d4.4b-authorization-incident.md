# D4.4b Authorization Incident — CATALOG-001 Marker / Artifact Overwrite

**Mode:** `READ_ONLY / NO_SIGNING / NO_PAYMENT / STRICTLY_OFFLINE` (remediation)  
**Request:** `CATALOG-001` · `GET https://agent402.tools/.well-known/x402`  
**Status:** Mitigated in-repo; human renewed authorization still required for any future live GET.

---

## 1. Sequence

1. Security gates completed (transport inspect → allowlist → offline tests → dry-run → single-use guard → args review).
2. First `--approved-live` run wrote the attempt marker **before** network I/O, performed the approved GET, and persisted success artifacts:
   - `docs/day4/evidence/agent402-full-resource-catalog.json`
   - analysis + shortlist + markdown companions
3. A post-success verification re-invocation of `--approved-live` was correctly **network-blocked** by the existing marker (`status: attemptBlocked`; transport not called).
4. An early CLI bug still wrote an empty `attemptBlocked` shell document over the good catalog artifacts.
5. Marker was cleared **out-of-band once** (human action) to restore artifacts via one restorative GET. Marker remains in place; further live runs stay blocked.
6. Success-only artifact writes were added; this document + exclusive marker create harden the remaining gap.

## 2. Root cause

Two independent failures compounded:

| Layer | Defect |
| --- | --- |
| CLI persistence | Artifact writes were gated on `--approved-live` rather than `status === "success"`, so a blocked re-run could overwrite success evidence with an empty shell. |
| Marker create (pre-hardening) | `exists-check` → write-temp → `rename` is not exclusive on POSIX: `rename(2)` replaces an existing destination, leaving a TOC-TOU window where a concurrent create could overwrite a peer marker. |

Network allowlisting and the “marker before I/O” rule worked; the bug was **post-block persistence** plus **non-exclusive marker finalization**.

## 3. Impact

- **Confidentiality / payment:** none — no signing, no payment, no extra provider URLs.
- **Integrity of evidence:** transient — success catalog could be replaced by an empty blocked shell until restorative re-fetch.
- **Authorization semantics:** live re-run stayed network-blocked; the defect did not silently re-approve HTTP. It did risk destroying local proof of the successful recovery.
- **D4.3c history:** not overwritten (separate paths).

## 4. Mitigations (implemented)

1. **Success-only artifact writes** in `recover-agent402-catalog.ts` — `attemptBlocked` / transport failures never persist catalog/analysis/shortlist/markdown.
2. **Exclusive marker create** via `writeFileSync(..., { flag: "wx" })` on the **final** marker path (`exclusive-wx-final-path`). No rename-overwrite path for markers.
3. Concurrent marker conflict maps to `status: attemptBlocked` (no throw past the guard that could confuse callers into writing artifacts).
4. CLI rejects `--force` / `--reset` / `--retry` / `--force-retry` / `--force-reset`.
5. Dry-run never writes or consumes the marker.
6. Offline regression tests cover blocked overwrite, concurrent race, failure-preserves-marker, dry-run non-consume.
7. **No new provider HTTP/DNS/RPC** while remediating.

## 5. Remaining risks

- Human out-of-band marker deletion still enables exactly one future live attempt — that is intentional and requires **renewed authorization**, not a CLI flag.
- Partial marker file after crash mid-write still blocks re-run (fail-closed); operators must not delete it without renewed auth.
- Filesystem semantics on exotic non-POSIX targets may differ; AgentHire assumes Node `wx` / `EEXIST` behavior.
- Restoring destroyed artifacts still requires either retained copies or a newly authorized live GET — offline code cannot invent the body.

## 6. Renewed-auth requirement

Any future live `CATALOG-001` GET requires:

1. Explicit human renewed authorization (new assignment / allowlist confirmation).
2. Out-of-band marker removal only after that authorization is recorded.
3. Re-running security gates (dry-run first; zero network).
4. Exactly one `--approved-live` attempt; marker written before I/O; no force/reset/retry flags.

Until then: **STRICTLY_OFFLINE** — analyze recovered artifacts only; do not call the provider.
