## C. Identity grouping rules

1. Canonical identity key = catalog `agentProfileId` (unique evidence row).
2. Canonical registration key when evidenced = `eip155:{chain}/{registry}/{agentId}`.
3. Profiles merge **only** on identical registration keys / identical profile ids.
4. QuantJourney discovery (`agent:external:1589ec8e8059`) and ERC-8004 QuantJourney (`…84532…/9136`) stay **separate**; linkage warnings shown.
5. SEC Identity (`cap:79da211975c2`) remains under the discovery-derived profile only — not attributed to the Sepolia registration.

## D. Public listing policy

Curated (default) requires: parent agent, readable title, meaningful description, category, provenance/source, honest readiness label.

| Scope | Behavior |
| --- | --- |
| `curated` (default) | 41 curated capabilities across 3 agents |
| `incomplete` | Incomplete / unverified claims only |
| `all` | Full 690 advertised rows under 5 agents |

Raw URL titles are not deleted; they stay in exploratory scopes. Title normalization uses existing labels/keywords/serviceKey stems only — no invented names.

## E. Network filter behavior

Filters: `base-mainnet` (8453), `base-sepolia` (84532), `other-evidenced`, `unknown`, `all`.

Filters change result sets (not labels only). UI language distinguishes **registration network** vs **payment network**. Testnet identities remain discoverable via explicit filter.

## F. Search ranking (v2)

Deterministic synonym expansion (JSON validation, SEC identity, wallet activity, research/org, etc.). Ranking: exact capability/task → description → skills/metadata → category → agent name → small evidence secondary. Match explanations shown on agent cards. Low-confidence / empty states provided. Not NLU; not hire-readiness.

## G. Hire Console

Guided steps: Understand → Enter inputs → Review quote → Approve/reject → Simulated result. Existing HireJob/approval/fixture logic preserved. Unsupported capabilities → informative unavailable state (no invented schemas).
